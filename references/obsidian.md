# Obsidian intake

Read this file only when the user asks to prepare or write an Obsidian note.

## Permission boundary

Preparing content and writing to a vault are different actions. Before writing, confirm only details that are missing:

1. Vault, folder, or existing note.
2. Note type and depth.
3. Whether to include, link, or omit the raw transcript.

Do not repeat a question when the user already supplied the answer.

## Default note

Use concise Markdown with:

- title;
- source URL or local source label;
- creator and date when known;
- duration;
- short summary;
- key ideas with timestamps;
- important visual evidence;
- claims, decisions, or action items;
- uncertainties and open questions;
- links to related notes when known.

Prefer distilled knowledge over archival transcript. Include the raw transcript only when the user requests it.

## Note types

- **Source note:** argument, evidence, important quotes, and links.
- **Lesson:** concepts, explanations, examples, and exercises.
- **Tutorial:** prerequisites, ordered steps, expected results, and failure points.
- **Demo review:** features, UI states, actions, results, and limitations.
- **Meeting note:** attendees when known, decisions, owners, actions, and deadlines.
- **Tool note:** purpose, setup, workflow, constraints, and useful commands.

## Verification

Before writing, verify the destination and the proposed filename. After writing, confirm the saved path and summarize what was added.
